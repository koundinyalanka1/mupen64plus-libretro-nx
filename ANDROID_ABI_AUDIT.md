# Android ABI audit

Scope: Android `armeabi-v7a` (32-bit ARM), `arm64-v8a` (64-bit ARM), and
`x86_64`. The audit covers architecture selection, compiler optimizations,
NEON geometry, CPU/RSP generated code, executable memory, and coroutine state.

## Issues and fixes

| Priority | Affected targets | Issue | Fix |
| --- | --- | --- | --- |
| High | x86_64, standalone Makefile | The `x86` substring branch also matched `x86_64`, selecting a 32-bit compiler, dynarec and assembler format. Android defaults still named obsolete GCC tools. | Select x86_64 first, use ELF64 assembly, and select NDK Clang wrappers for each ABI. |
| High | All Android targets | Global `-ffast-math` defeated the Android NEON floating-point safeguard and could change NaN, signed-zero and expression evaluation behavior in emulation code. | Keep release optimization and explicit SIMD, disable fast math and implicit FP contraction for Android, including the final link. |
| High | ARMv7, ARM64, multi-ABI NDK builds | ARM64 omitted NEON geometry; ARMv7 selected NEON sources without the matching geometry defines. Common flags and plugin defaults could leak between ABI evaluations. | Share NEON feature defines with source selection; enable both ARM paths; isolate ABI flags while preserving incoming plugin defaults. |
| High | All NDK targets | Assembly offsets were not generated by the NDK build, allowing missing or stale source-tree headers from another ABI. | Generate offsets from each ABI's compiler-produced object under its own output directory, with explicit assembly prerequisites. |
| High | ARM64 | The register allocator and far-branch trampolines used Android's reserved `x18`. | Exclude `x18` and reserve the already-preserved `x28` for trampoline scratch. |
| High | ARM64 | The far-jump symbol-table loop divided its byte size by four although entries are pointer-sized. Missing targets could read past the table. | Compute the element count using `sizeof(array) / sizeof(array[0])`. Apply the same portable expression to ARM32. |
| High | All three dynarecs | The register-culling pass accessed register arrays with a loop counter that could already equal `HOST_REGS`, reading past their bounds and failing to remove overwritten mappings. | Check overwritten mappings inside a bounded register loop. |
| High | ARMv7, ARM64 | Dirty instruction-cache runs reaching bitmap bit 31 were cleared without being flushed; cache-range ends were also off by one. | Flush every completed run, use exclusive end addresses, and use unsigned bit masks. |
| High | All targets, especially devices with 16 KB pages | The CPU cache assumed 4 KB alignment and ignored failed protection calls. The RSP allocator rounded to 4 KB, treated `MAP_FAILED` as usable, and could overflow size calculations. | Use runtime host page sizes; check protection/allocation failures and size overflow; fall back to the pure interpreter when CPU dynarec initialization fails. Align Android ELF load segments to 16 KB. |
| High | ARM64 | Coroutine switches omitted the callee-preserved low halves of SIMD registers `v8`–`v15`. | Save, restore and initialize `d8`–`d15` in coroutine contexts. |
| Medium | ARMv7, ARM64 | NEON lighting always used the primary light colors; scalar lighting uses alternate colors for odd vertices. | Select `rgb` or `rgb2` per vertex throughout scalar tails and SIMD batches. |
| Medium | ARMv7, ARM64 | Zero-length normalization performed invalid reciprocal refinement. The existing zero mask also erased tiny nonzero vectors when their squared length underflowed. | Substitute a safe refinement input for zero squared lengths and select an exact unit scale, preserving scalar zero/underflow behavior and NaN propagation. |
| Medium | Standalone Makefile | Dependency files were included but not generated, allowing edits to included headers/sources to leave stale objects. | Emit compiler dependency files for C, C++ and preprocessed assembly, and keep `all` as the default goal when these files are included. Restore a missing GAS offsets header from its NASM counterpart. |

Existing graphics/state changes in the working tree were retained. The NEON
normalization changes extend the existing zero-vector fix.

## Validation

Verified on 2026-09-20 with Android NDK 28.2.13676358 and a native Apple Silicon
host. All 21 host regressions passed, including seven dynarec checks under
AddressSanitizer/UndefinedBehaviorSanitizer. All six builds below compiled and
linked successfully; ELF architecture and 16 KB load-segment alignment were
checked on each resulting library. Standalone incremental builds also passed
the up-to-date check.

| ABI | NDK / GLES2 | Standalone Makefile / GLES3 | ELF |
| --- | --- | --- | --- |
| armeabi-v7a | Passed | Passed | ARM, ELF32 |
| arm64-v8a | Passed | Passed | AArch64, ELF64 |
| x86_64 | Passed | Passed | x86-64, ELF64 |

Host regressions:

```sh
python3 -m unittest discover -s tests -v
```

These cover ABI selection and flag isolation, existing Android graphics and
frame-skip behavior, NEON/scalar lighting parity, zero/underflow normalization,
coroutine register preservation, JIT allocation failures and page alignment,
and production dynarec functions under AddressSanitizer/UndefinedBehaviorSanitizer.

NDK build from the repository root (set `NDK_DIR` to an installed NDK):

```sh
"$NDK_DIR/ndk-build" -j8 \
  NDK_PROJECT_PATH=libretro/jni \
  APP_BUILD_SCRIPT=libretro/jni/Android.mk \
  NDK_APPLICATION_MK=libretro/jni/Application.mk \
  APP_ABI="armeabi-v7a arm64-v8a x86_64" \
  NDK_OUT=/tmp/m64-android/obj NDK_LIBS_OUT=/tmp/m64-android/lib
```

On this Apple Silicon host, NDK r28's bundled x86 host `yasm` could not execute.
The build was validated with the installed native assembler using
`TARGET_ASM=/opt/homebrew/bin/nasm` for these three targets.

Standalone examples, using a clean output tree for each architecture:

```sh
make platform=android-arm64-v8a-gles3 ANDROID_NDK="$NDK_DIR"
make platform=android-armeabi-v7a-gles3 ANDROID_NDK="$NDK_DIR"
make platform=android-x86_64-gles3 ANDROID_NDK="$NDK_DIR"
```

On-device ROM/gameplay, GPU behavior, sustained performance, and battery usage
require device testing. These changes do not establish an FPS improvement or
complete emulation compatibility.

The ABI constraints follow the official [Android ABI guide](https://developer.android.com/ndk/guides/abis),
[Android page-size guidance](https://developer.android.com/guide/practices/page-sizes),
and [AArch64 calling convention](https://github.com/ARM-software/abi-aa/blob/main/aapcs64/aapcs64.rst).
